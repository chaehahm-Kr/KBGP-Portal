# MAN-B-PERM-001: K SELECT Brand Portal 사용자, 역할 및 권한 관리 가이드
## Permissions & User Management Guide

---

# 제1장. 개요 및 권한 체계 아키텍처

## 1.1 개요 및 목적
K SELECT NETWORK 파트너 포털은 한국 K-Beauty 브랜드사가 북미 시장 진출 과정에서 안전하고 효율적으로 협업할 수 있도록 강력한 **사용자 관리(User Management)** 및 **역할 기반 접근 제어(RBAC / ACL)** 시스템을 제공합니다.

회사 관리자(`company_admin`)는 같은 회사의 동료들을 포털에 초대하고, 각 담당자의 업무 범위에 맞추어 5가지 역할 프리셋과 9개 메뉴별 세부 권한을 유연하게 설정할 수 있습니다. 또한, 회사의 소중한 브랜드 자산과 거래 데이터는 멀티테넌트 보안 아키텍처를 통해 타사와 안전하게 분리되어 보호됩니다.

---

## 1.2 5단계 권한 레이어 구조
K SELECT 포털의 보안 및 접근 제어는 다음과 같이 **5개의 독립된 계층**으로 분리되어 체계적으로 동작합니다.

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 1. 사용자 인증 (Authentication)                                          │
│    - Supabase Auth를 통한 로그인 이메일 및 비밀번호 검증                 │
├─────────────────────────────────────────────────────────────────────────┤
│ 2. 애플리케이션 프로필 (Application Profile)                             │
│    - 포털 파티션 식별: 파트너 포털(portal) / 어드민(admin) / 리테일(retailer)│
├─────────────────────────────────────────────────────────────────────────┤
│ 3. 회사 소속 멤버십 (Company Membership)                                │
│    - 단일 회사(company_id) 1:1 바인딩 및 DB 역할(company_admin/staff)    │
├─────────────────────────────────────────────────────────────────────────┤
│ 4. 역할 프리셋 및 메뉴별 ACL (Role Presets & ACL Matrix)                │
│    - 5가지 역할 프리셋 및 9개 업무 영역에 대한 4단계 권한 매트릭스      │
├─────────────────────────────────────────────────────────────────────────┤
│ 5. 데이터베이스 행 레벨 보안 (PostgreSQL Row-Level Security)            │
│    - DB 커널 레벨에서 본인 회사(company_id) 데이터만 격리 조회          │
└─────────────────────────────────────────────────────────────────────────┘
```

# 제2장. 소속 멤버 목록 및 상태 관리

## 2.1 소속 멤버 대시보드 (`/portal/company/users`)
회사 관리자(`company_admin`)는 포털 좌측 하단 **[설정] $\rightarrow$ [사용자 관리]** 메뉴에서 현재 회사에 등록된 모든 팀원의 목록과 권한 현황을 한눈에 조회할 수 있습니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-001.png` (소속 멤버 목록 대시보드)

### 주요 표시 항목 및 뱃지 안내
1. **이름 및 식별 뱃지**:
   - 팀원의 한글 성명 및 영문 성명이 표시됩니다.
   - `[본인]`: 현재 로그인한 관리자 본인 계정임을 나타냅니다.
   - `[최초 관리자]`: 회사를 최초로 등록한 초기 소유자(Initial Owner) 계정으로, 안전을 위해 삭제가 보호됩니다.
   - `[대표 담당자]`: 회사의 주 컨택 포인트(Primary Contact)로 지정된 담당자입니다.
2. **이메일 / 연락처**:
   - 로그인에 사용되는 공식 이메일 주소 및 국제 표준 형식(`📞`)의 비즈니스 연락처가 표시됩니다.
3. **직함 / 부서**:
   - 담당자의 사내 직함(예: 대표이사, 부장, 매니저) 및 소속 부서(예: 해외영업팀, 마케팅팀)가 노출됩니다.
4. **역할 (Role Preset)**:
   - 팀원에게 부여된 역할이 컬러 뱃지로 명확히 구분됩니다:
     - `관리자 (Admin)`: 인디고 뱃지
     - `매니저 (Manager)`: 퍼플 뱃지
     - `담당자 (Staff)`: 블루 뱃지
     - `조회자 (Viewer)`: 그레이 뱃지
     - `접근제한 (Restricted)`: 앰버 뱃지
5. **가입 상태 (Join Status)**:
   - `가입완료` (초록 뱃지): 초대를 수락하고 비밀번호 설정을 완료하여 정상 이용 중인 상태입니다.
   - `초대됨` (노랑 뱃지): 초대 이메일이 발송되었으나 아직 비밀번호를 설정하지 않은 대기 상태입니다.
   - `초대만료` (빨강 뱃지): 초대 발송 후 7일 유효기간이 초과된 상태로, 관리자가 재초대를 발송해야 합니다.
6. **이용 상태 (Usage Status)**:
   - `정상이용` (초록 뱃지): 포털 로그인이 정상 허용된 상태입니다.
   - `대기중` (회색 뱃지): 초대 대기 중인 상태입니다.
   - `이용정지` (빨강 뱃지): 관리자에 의해 일시 정지(`suspended`)된 상태로, 포털 로그인이 차단됩니다.

# 제3장. 신규 멤버 초대 및 역할 프리셋 설정

## 3.1 신규 멤버 초대 프로세스
팀원을 포털에 추가하려면 소속 멤버 목록 상단의 **`[+ 사용자 초대하기]`** 버튼을 클릭합니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-002.png` (신규 멤버 초대 모달)

### 필수 입력 및 검증 필드
1. **영문 성 및 영문 이름 (English Name) [필수]**:
   - 북미 바이어 및 현지 리테일러와의 글로벌 커뮤니케이션을 위해 영문 성(`Last Name`)과 영문 이름(`First Name`)을 필수로 입력합니다.
   - 영문자(A-Z, a-z), 공백, 하이픈(-)만 허용됩니다.
2. **한글 성 및 한글 이름 (Korean Name) [선택]**:
   - 국내 커뮤니케이션을 위한 한글 성과 이름을 입력할 수 있습니다.
3. **로그인 이메일 (Login Email) [필수]**:
   - 초대 이메일을 수신하고 로그인 아이디로 사용할 이메일 주소를 입력합니다.
   - 시스템 전사 중복 검증이 적용되어, 이미 타사에 가입되어 있거나 활성화된 이메일은 중복 초대가 방지됩니다.

---

## 3.2 5대 역할 프리셋 (Role Presets)
초대 모달에서 팀원의 업무 특성에 맞는 **역할 템플릿(Role Preset)**을 선택하면 표준 권한 매트릭스가 자동으로 지정됩니다.

```text
┌─────────────────┬────────────────────────────────────────────────────────┐
│ 역할 프리셋      │ 설명 및 표준 권한 범위                                   │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 접근 제한       │ 모든 사업 메뉴 접근불가 (본인 계정 정보만 확인 가능)       │
│ (Restricted)    │                                                        │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 조회 사용자     │ 기본 초대 권한. 모든 일반 업무 메뉴의 단순 조회 전용     │
│ (Viewer)        │ (송금 계좌 정보 및 계약 문서는 접근불가)                 │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 담당자          │ 제품, 브랜드, 주문, 입점신청 등 실무 영역 생성/수정 가능 │
│ (Staff)         │ (정산은 조회만 가능, 계좌/계약 문서는 접근불가)          │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 매니저          │ 제품, 주문 관리 및 정산 수정 권한 보유                   │
│ (Manager)       │ (계좌 정보 및 계약 문서는 조회 가능)                     │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 관리자          │ 회사 전 메뉴 생성/수정/삭제, 팀원 초대 및 권한 변경 등   │
│ (Admin)         │ 회사 포털 내 최고 관리 권한                            │
└─────────────────┴────────────────────────────────────────────────────────┘
```

> [!NOTE]
> **DB 멤버십 역할과의 관계**:
> 데이터베이스 레벨에서는 `company_admin`과 `company_staff` 두 가지 멤버십으로 분류됩니다. `admin` 프리셋은 `company_admin`으로 저장되어 최고 권한을 부여받으며, 나머지 4개 프리셋은 `company_staff`로 저장된 후 매트릭스에 의해 권한이 제어됩니다.

# 제4장. 메뉴별 상세 권한(ACL) 매트릭스 설정

## 4.1 9개 업무 영역 $\times$ 4단계 접근 권한
K SELECT 포털은 포털 내 모든 메뉴를 **9개 카테고리**로 세분화하고, 각 영역마다 **4단계 접근 레벨**을 부여할 수 있는 세밀한 ACL(Access Control List) 매트릭스 에디터를 제공합니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-003.png` (메뉴별 상세 권한 매트릭스 에디터)

### 4단계 접근 권한 레벨
- **`접근불가 (none, 0단계)`**: 해당 메뉴가 사이드바에서 숨겨지거나 잠금(🔒) 처리되며, 접근이 차단됩니다.
- **`조회전용 (read, 1단계)`**: 등록된 데이터와 목록을 열람할 수 있으나 생성, 수정, 삭제는 제한됩니다.
- **`생성/수정 (write, 2단계)`**: 신규 데이터 등록 및 기존 정보 수정이 가능합니다.
- **`생성/수정/삭제 (manage, 3단계)`**: 생성, 수정뿐만 아니라 데이터 삭제 및 최종 승인/취소 등 전권을 행사합니다.

### 9개 업무 카테고리 매트릭스 기준표
| 메뉴 카테고리 | Restricted | Viewer (기본) | Staff | Manager | Admin |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **입점 신청서 (`application`)** | `none` | `read` | `write` | `write` | `manage` |
| **브랜드 관리 (`brands`)** | `none` | `read` | `write` | `write` | `manage` |
| **제품 관리 (`products`)** | `none` | `read` | `write` | `manage` | `manage` |
| **주문 관리 (`orders`)** | `none` | `read` | `write` | `manage` | `manage` |
| **정산 / 인보이스 (`finance`)** | `none` | `read` | `read` | `write` | `manage` |
| **문의 지원 (`support`)** | `none` | `read` | `write` | `manage` | `manage` |
| **회사 기본 정보 (`company_info`)**| `none` | `read` | `read` | `write` | `manage` |
| **송금 계좌 정보 (`bank_info`)** | `none` | `none` | `none` | `read` | `manage` |
| **계약 및 문서 (`agreements`)** | `none` | `none` | `none` | `read` | `manage` |

> [!TIP]
> **개별 카테고리 오버라이드 (Custom Override)**:
> 역할 템플릿(예: Staff)을 선택한 후에도, 특정 카테고리(예: `finance` 또는 `bank_info`)의 라디오 버튼을 개별적으로 클릭하여 원하는 권한 레벨로 자유롭게 맞춤 조정할 수 있습니다.

# 제5장. 멤버 정보 수정, 6대 업무 배정 및 멤버 제거

## 5.1 멤버 정보 및 권한 수정
팀원의 직함, 연락처, 이용 상태 또는 권한을 변경하려면 소속 멤버 목록에서 해당 팀원 우측의 **`[수정]`** 버튼을 클릭합니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-004.png` (멤버 정보 및 권한 수정 모달)

- **기본 정보 변경**: 성명, 직함, 부서, 연락처 수정.
- **이용 제한 상태**: `Active (정상 이용)` $\leftrightarrow$ `Deactive (이용 일시정지)` 전환. 일시정지 시 해당 사용자의 세션이 즉시 무효화되어 로그인이 차단됩니다.
- **대표 담당자 지정**: 회사의 주 컨택 포인트로 지정할 경우 체크박스를 선택합니다.

---

## 5.2 6대 공식 담당 업무 배정
수정 모달 하단의 **`3. 담당 업무 및 알림 배정`** 섹션에서는 K SELECT 네트워크 운영을 위한 6대 핵심 실무 영역의 주 담당자와 이메일 알림 수신 여부를 설정할 수 있습니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-005.png` (6대 담당 업무 배정 테이블)

| 업무 코드 | 공식 업무명 | 주요 업무 범위 | 주 담당자 설정 |
| :--- | :--- | :--- | :---: |
| `company_apply` | **회사·신청** | 회사 정보, 브랜드 등록, 입점 신청, 보완 및 심사 업무 | 1명 지정 |
| `contract` | **계약** | 기본계약서 확인, 계약 조건 검토, 전자 서명 및 갱신 | 1명 지정 |
| `product_cert` | **제품·콘텐츠·인증** | 제품 스펙, 성분, MoCRA/FDA 규제 서류, 마케팅 콘텐츠 | 1명 지정 |
| `pricing_quote` | **가격·견적** | 공급 단가, 원가 검토, 견적서 제출 및 가격 협의 | 1명 지정 |
| `logistics_inventory`| **발주·물류·재고** | 발주서 확인, 상품 준비(Goods Ready), 선적 및 통관 | 1명 지정 |
| `settlement_inquiry` | **정산·문의** | 인보이스 발행, 정산 대금 수령, 1:1 문의 및 이슈 대응 | 1명 지정 |

> [!IMPORTANT]
> **담당 업무 배정 $\neq$ 메뉴 접근 권한**:
> 6대 담당 업무 배정은 **K SELECT 운영팀과의 소통 책임자 지정 및 관련 이메일 알림 수신 라우팅 목적의 메타데이터**입니다. 포털 메뉴 접근이나 데이터 수정 권한은 상단의 ACL 매트릭스에 의해서만 결정됩니다.

## 5.3 멤버 제거 및 안전 보호 정책
퇴사 등의 사유로 팀원을 회사에서 제외해야 하는 경우, 목록 또는 수정 모달에서 **`[멤버 제거]`**를 실행할 수 있습니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-008.png` (멤버 제거 확인 모달)

### 3대 안전 보호 규칙
1. **최초 관리자(Initial Owner) 보호**:
   - 회사를 최초 개설한 초기 관리자 계정은 시스템 보호 규칙에 의해 회사에서 임의로 삭제할 수 없습니다.
2. **마지막 관리자(Last Admin) 보호**:
   - 회사에 활성 관리자가 1명만 남은 경우, 회사가 관리자 없는 상태가 되는 것을 방지하기 위해 해당 관리자의 삭제 또는 강등이 차단됩니다.
3. **본인 계정 셀프 삭제 차단**:
   - 관리자 본인 계정은 직접 삭제할 수 없으며, 다른 관리자 계정을 통해 처리해야 합니다.
4. **회사 비즈니스 데이터 영구 보존**:
   - 멤버가 제거되더라도 해당 멤버가 등록한 브랜드, 제품, 발주서, 정산 데이터는 개인 계정이 아닌 **회사(`company_id`) 자산**이므로 일체 유실되지 않고 안전하게 보존됩니다.

# 제6장. 초대 수락 및 본인 계정 관리 (My Account)

## 6.1 초대 수락 및 비밀번호 설정 (`/portal/invite/accept`)
초대 이메일을 수신한 신규 팀원은 메일 내 **`[초대 수락 및 비밀번호 설정]`** 버튼을 클릭하여 가입 온보딩 페이지로 접속합니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-006.png` (초대 수락 및 비밀번호 설정 화면)

### 온보딩 및 보안 가이드
- **7일 유효기간**: 초대 링크는 보안을 위해 발송 후 7일간 1회만 사용 가능합니다. 기한이 지난 경우 관리자에게 재초대를 요청해야 합니다.

# 제7장. 어드민 지원 및 테넌트 데이터 보안

## 7.1 K SELECT 어드민 지원 및 데이터 격리
K SELECT NETWORK 관리자 콘솔(`/admin/*`)은 브랜드사의 파트너십과 시스템 운영을 체계적으로 지원합니다.

> 📷 **스크린샷 배치**: `SCR-B-PERM-009.png` (어드민 회사 상세 — 사용자 관리 탭)

### 멀티테넌트 데이터 격리 및 지원 세션
1. **데이터베이스 행 레벨 보안 (RLS)**:
   - 모든 비즈니스 데이터 테이블(회사, 브랜드, 제품, 주문, 정산 등)에 PostgreSQL RLS 정책이 적용되어, 타 브랜드사의 데이터는 원천적으로 조회되지 않습니다.
2. **어드민 지원 세션 (Impersonation)**:
   - 파트너사의 기술적 문제 해결이나 심사 보완을 위해 K SELECT 직원이 지원 세션을 실행할 경우, 상단에 **지원 세션 안내 배너**가 명확히 표시되어 투명하고 안전한 운영을 보장합니다.

# 제8장. 자주 묻는 질문 (FAQ 7선)

### Q1. 한 명의 직원이 여러 회사의 포털 계정에 동시에 소속될 수 있나요?
**A1.** 아니오, 불가능합니다. K SELECT NETWORK는 엄격한 테넌트 보안을 위해 **1 사용자 이메일 = 1 회사 계정**의 1:1 바인딩 원칙을 적용합니다. 다른 회사에 참여해야 하는 경우 별도의 비즈니스 이메일 계정으로 초대받으셔야 합니다.

### Q2. 역할 템플릿(Preset)을 선택한 뒤 특정 메뉴의 권한만 따로 바꿀 수 있나요?
**A2.** 네, 가능합니다. 5가지 역할 프리셋(Viewer, Staff, Manager 등)을 클릭하여 기본 권한을 불러온 후, 우측 매트릭스에서 원하는 메뉴 카테고리의 라디오 버튼을 개별 클릭하여 커스텀 권한으로 저장할 수 있습니다.

### Q3. 발송된 초대 링크가 만료되었다고 표시됩니다. 어떻게 해야 하나요?
**A3.** 초대 링크는 보안을 위해 발송 후 7일간만 유효합니다. 회사 관리자(`company_admin`)에게 소속 멤버 목록 화면에서 해당 사용자의 **`[재초대]`** 버튼을 눌러 새 초대장을 발송해 달라고 요청해 주시기 바랍니다.

### Q4. 6대 담당 업무 배정에서 주 담당자로 지정되면 포털 권한도 자동으로 부여되나요?
**A4.** 아닙니다. 6대 담당 업무 배정은 K SELECT 운영팀과의 실무 소통 책임자 지정 및 이메일 알림 수신을 위한 설정입니다. 실제 포털 화면 접근 및 기능 실행 권한은 ACL 매트릭스 설정에 의해서만 결정됩니다.

### Q5. 최초 관리자(Initial Owner) 계정을 다른 담당자로 변경하거나 삭제할 수 있나요?
**A5.** 회사를 처음 등록한 최초 관리자 계정은 시스템 보호 정책에 따라 임의 삭제가 불가능합니다. 최초 관리자 권한의 이양이나 대표자 변경이 필요한 경우 K SELECT 공식 지원팀(1:1 문의)으로 문의해 주시기 바랍니다.

### Q6. 팀원이 퇴사하여 계정을 삭제하면 그동안 등록한 제품이나 발주 내역도 함께 삭제되나요?
**A6.** 아니오, 삭제되지 않습니다. 포털에 등록된 모든 브랜드, 제품, 발주서, 인보이스 데이터는 개인 사용자가 아닌 **회사(`company_id`)의 공식 자산**으로 영구 귀속되므로, 멤버를 제거해도 회사의 비즈니스 데이터는 안전하게 보존됩니다.

### Q7. 직원의 이용 상태를 '이용 일시정지'로 변경하면 어떻게 되나요?
**A7.** 해당 직원의 활성 로그인 세션이 즉시 무효화되며 포털 접속이 차단됩니다. 추후 담당 업무에 복귀할 경우 관리자가 언제든지 `Active (정상 이용)`으로 다시 활성화할 수 있습니다.
